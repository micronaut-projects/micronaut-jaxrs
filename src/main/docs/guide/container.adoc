Micronaut JAX-RS supports defining Jakarta RESTful Web Services (JAX-RS) server resources in a Micronaut application.

Include the following server dependency:

dependency:micronaut-jaxrs-server[scope="implementation",groupId="io.micronaut.jaxrs"]

The server module is the compile-time optimized runtime. It is not limited to basic annotation translation; it supports the main Jakarta REST server programming model without requiring the aggregate `micronaut-jaxrs-jakarta` module.

==== Server Module Coverage

With the annotation processor enabled, `micronaut-jaxrs-server` supports:

* application roots and resource selection with link:{jaxrsapi}/jakarta/ws/rs/ApplicationPath.html[`@ApplicationPath`] and link:{jaxrsapi}/jakarta/ws/rs/core/Application.html[`Application`];
* resource classes, resource methods, subresource locators, and recursive subresource locators declared with link:{jaxrsapi}/jakarta/ws/rs/Path.html[`@Path`];
* standard HTTP method annotations, including `@GET`, `@POST`, `@PUT`, `@PATCH`, `@DELETE`, `@HEAD`, `@OPTIONS`, and custom methods declared with link:{jaxrsapi}/jakarta/ws/rs/HttpMethod.html[`@HttpMethod`];
* media-type matching with link:{jaxrsapi}/jakarta/ws/rs/Consumes.html[`@Consumes`] and link:{jaxrsapi}/jakarta/ws/rs/Produces.html[`@Produces`], including Jakarta REST response selection parameters;
* request parameter binding with `@PathParam`, `@QueryParam`, `@HeaderParam`, `@CookieParam`, `@MatrixParam`, `@FormParam`, `@DefaultValue`, and `@Encoded`;
* scalar, array, and iterable request parameter values through Micronaut conversion or registered link:{jaxrsapi}/jakarta/ws/rs/ext/ParamConverterProvider.html[`ParamConverterProvider`] beans;
* form URL-encoded and multipart form binding, including link:{jaxrsapi}/jakarta/ws/rs/core/EntityPart.html[`EntityPart`] values;
* unannotated entity body parameters on resource methods;
* resource constructor parameters for supported request and context values;
* context injection with link:{jaxrsapi}/jakarta/ws/rs/core/Context.html[`@Context`] for Jakarta REST context objects and Micronaut beans;
* provider discovery from Micronaut beans and `@Provider` classes processed at compile time;
* `@Priority`, name binding, pre-matching filters, container request and response filters, reader and writer interceptors, features, dynamic features, exception mappers, context resolvers, message body readers, and message body writers;
* Jakarta REST response handling with link:{jaxrsapi}/jakarta/ws/rs/core/Response.html[`Response`], link:{jaxrsapi}/jakarta/ws/rs/core/GenericEntity.html[`GenericEntity`], link:{jaxrsapi}/jakarta/ws/rs/core/StreamingOutput.html[`StreamingOutput`], and SSE contexts.

The default context set includes `Application`, `Configuration`, `HttpHeaders`, `Providers`, `Request`, `ResourceContext`, `ResourceInfo`, `SecurityContext`, `Sse`, `SseEventSink`, and `UriInfo`.

==== Unsupported Without Reflection

The default server module avoids reflection fallback behavior. Add the reflection module when an application needs Jakarta REST behavior that cannot be represented through generated Micronaut metadata:

dependency:micronaut-jaxrs-reflection[scope="implementation",groupId="io.micronaut.jaxrs"]

Without `micronaut-jaxrs-reflection`, the following fallback cases are not supported:

* request-scoped resource field injection for `@PathParam`, `@QueryParam`, `@HeaderParam`, `@CookieParam`, `@MatrixParam`, `@FormParam`, or `@BeanParam` fields;
* request bean binding for `@BeanParam`, including nested request beans that need runtime binding;
* reflective parameter conversion using a public `String` constructor, static `valueOf(String)`, or static `fromString(String)` when no Micronaut converter or `ParamConverterProvider` bean is available;
* provider classes registered by type through `Feature`, `DynamicFeature`, or related Jakarta REST runtime APIs when the provider is not already a Micronaut bean;
* Jakarta REST SE bootstrap fallback.

The processor is strict by default and fails compilation for unsupported fallback shapes. If you intentionally rely on reflection-backed compatibility behavior, see <<specCompliance,Spec Compliance>> for the `micronaut.jaxrs.fail.on.unsupported=false` processor option used by the compliance profile.

==== Unsupported Without The Aggregate

The `micronaut-jaxrs-jakarta` module is an aggregate for applications that want the broad Jakarta REST compliance stack from one dependency:

dependency:micronaut-jaxrs-jakarta[scope="implementation",groupId="io.micronaut.jaxrs"]

If an application uses only `micronaut-jaxrs-server`, the following are not added automatically:

* the standalone Jakarta REST client implementation from `micronaut-jaxrs-client`;
* the reflection fallback module described above;
* XML, JAXB, `Source`, `DataSource`, and `JAXBElement` entity providers from `micronaut-jaxrs-xml`;
* JSON-B entity providers and optional JSON-B API dependencies from the aggregate module.

These capabilities can also be added individually when the full aggregate is not desired. Micronaut Security role integration and Servlet request context integration remain separate optional modules.

==== SecurityContext and Micronaut Security

When injecting the link:{jaxrsapi}/jakarta/ws/rs/core/SecurityContext.html[SecurityContext] by default the injected instance is not aware of https://micronaut-projects.github.io/micronaut-security/latest/guide/[Micronaut Security] and methods like `isUserInRole` always return `false`.

To integrate the JAX-RS support with Micronaut Security add the following dependency:

dependency:micronaut-jaxrs-server-security[scope="implementation",groupId="io.micronaut.jaxrs"]

With the above dependency in place the `SecurityContext.isUserInRole` method will return `true` if the role is found within Micronaut Security's https://micronaut-projects.github.io/micronaut-security/latest/api/io/micronaut/security/authentication/Authentication.html#getRoles--[Authentication.getRoles()] method.
See https://micronaut-projects.github.io/micronaut-security/latest/guide/#retrievingAuthenticatedUser[Retrieving the authenticated user] for more information.
