Micronaut JAX-RS implements https://jakarta.ee/specifications/restful-ws/4.0/[Jakarta RESTful Web Services 4.0]: the server, the client and the Java SE bootstrap. The implementation is verified with the Jakarta RESTful Web Services 4.0.1 TCK, which runs with an empty exclusion list, once with the reflection module on the classpath and once with only the metadata the annotation processors generate.

==== Modules

[cols="1,3"]
|===
|Module|Content

|`micronaut-jaxrs-processor`
|The annotation processor: the metadata of the resources, providers, `Application` subclasses and parameter conversions. Required at compile time.

|`micronaut-jaxrs-server`
|The server: root resources and sub-resources, request matching (JAX-RS 3.7), content negotiation, entity providers, filters and interceptors with name binding, `Feature` and `DynamicFeature`, exception mappers, parameter converters, context resolvers, `@Context` injection, `ResourceContext`, asynchronous responses, server-sent events, multipart entities and the Java SE bootstrap.

|`micronaut-jaxrs-client`
|The client API: `ClientBuilder`, `WebTarget`, synchronous, asynchronous and reactive invokers, client filters and interceptors, and `SseEventSource`.

|`micronaut-jaxrs-standard-providers`
|The standard entity providers that need other APIs: `File`, `DataSource`, `Source`, JAXB, JSON-P and JSON-B, see <<container, Container API>>.

|`micronaut-jaxrs-reflection`
|Reflection, for classes the annotation processors never saw, see below.

|`micronaut-jaxrs-server-security`
|A `SecurityContext` backed by Micronaut Security.

|`micronaut-jaxrs-servlet`
|The servlet types a resource can inject with `@Context`.
|===

==== Reflection

The resources, providers and `Application` subclasses compiled with `micronaut-jaxrs-processor` need no reflection: they are created, injected and routed from their generated bean definitions and introspections, which also works in a GraalVM native image.

Some classes are only known at runtime, for example a provider of a library compiled without the processor, which an `Application` or a `Feature` registers by class, or an instance whose `@Context` fields have no generated metadata. Such classes need the reflection module on the runtime classpath:

dependency:micronaut-jaxrs-reflection[scope="runtimeOnly",groupId="io.micronaut.jaxrs"]

Without it, the implementation uses only the generated metadata and fails with an error naming the class and the module where reflection would be needed. In a native image, the classes the reflection module reads must also be registered for reflection.

==== Deviations from the Specification

The following behaviors differ from the specification on purpose, to keep existing Micronaut JAX-RS applications working:

* A request without an entity is not answered with 415 when its `Content-Type` does not match the `@Consumes` of the resource method; only a request with an entity is.
* A class that implements an interface annotated with `@Path` is a root resource with that path. The specification does not inherit class annotations from interfaces (JAX-RS 3.6).
* A resource method parameter without an annotation, whose type is a context type (`HttpHeaders`, `UriInfo`, `SecurityContext`, `Request`, `Cookie`, `Application`, `Configuration`, `Providers`, `ResourceContext`, `ResourceInfo`, `HttpRequest` and the servlet types), is injected as if it was annotated with `@Context`, instead of being the entity parameter.

==== Limitations

* One `Application` per application context: its `@ApplicationPath`, classes, singletons, properties and features apply to all JAX-RS resources. Define one `Application` bean, or name the one to use with `micronaut.jaxrs.application`.
* The request entity of a resource method is read into memory before the readers and the reader interceptors run, up to `micronaut.server.max-request-size`. A resource method reading an `InputStream` reads that buffer.
* `RuntimeDelegate.createEndpoint` throws an `UnsupportedOperationException`, which the specification allows: use the Micronaut server, or `SeBootstrap.start` to start one for an `Application`.
* On a server that is not a servlet container, a `@Context HttpServletRequest` is a read-only view of the Micronaut request, without servlet context, session, request dispatcher or asynchronous processing, and its entity stream is read by JAX-RS. There is no stub of `HttpServletResponse` or `ServletContext`.
* Jakarta Bean Validation of resources (JAX-RS chapter 7) is not implemented by the JAX-RS runtime. Micronaut Validation validates the parameters and return values of resources that are beans, with the status codes of Micronaut Validation, see <<container, Container API>>.
